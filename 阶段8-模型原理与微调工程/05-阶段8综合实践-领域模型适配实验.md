# 阶段 8 综合实践：领域模型适配实验

## 一、项目目标

选择一个小型开源指令模型，为阶段 3/4 的 Agent 任务做一次参数高效微调，并用统一评测证明它是否值得保留。

建议场景：

- 企业运维工具选择和参数生成；
- 研发需求分析和风险分类；
- 固定格式的技术报告生成。

## 二、实验流程

```text
定义任务和停止标准
  -> 清洗、脱敏、版本化数据
  -> 基座模型基线
  -> Prompt / Tool Schema 基线
  -> LoRA 或 QLoRA
  -> 统一评测
  -> 量化推理对比
  -> 发布或回滚决策
```

## 三、里程碑

### M1：问题定义

- 明确微调解决的问题；
- 说明为什么不是 RAG、Prompt 或 Workflow 更合适；
- 定义质量、延迟、成本和安全门槛。

### M2：数据集

- 准备并脱敏训练数据；
- 设计独立测试集；
- 覆盖正常、失败、越权、无答案和边界样本；
- 记录数据版本和来源。

### M3：SFT / LoRA 实验

- 固定基座、Tokenizer 和 Chat Template；
- 保存训练配置和 adapter；
- 记录显存、耗时、Loss 和检查点；
- 至少完成一次可复现训练。

### M4：评测

- 与基座模型和 Prompt 基线比较；
- 测 Tool Call Accuracy、Task Completion、结构化输出和安全通过率；
- 把失败样本回灌 Golden Dataset；
- 判断是否存在过拟合或灾难性遗忘。

### M5：推理部署

- 对比 BF16/FP16 与量化版本；
- 测 TTFT、P95、吞吐、显存和单请求成本；
- 接入模型版本、Trace 和回滚策略。

README 至少回答：

- 为什么选择微调；
- 为什么选择 LoRA/QLoRA；
- 数据规模和脱敏方式；
- 基座与微调模型的指标差异；
- 量化后的质量、延迟和成本变化；
- 哪些任务仍然应该使用 RAG 或工具；
- 发布、灰度和回滚方式。

## 五、验收标准

- 训练实验可复现；
- 数据集和模型版本可追踪；
- 微调模型至少在一个目标指标上有实测收益；
- 安全指标不能退化；
- 量化和部署数据来自真实压测；
- README 明确写出微调不适用的边界；
- 如果微调没有收益，能够基于数据做出“不发布”的结论。
