# 量化、推理与模型服务

## 一、为什么学习量化

量化用更低精度表示权重或激活，通常可以降低显存和推理成本，但可能带来精度、吞吐或兼容性变化。量化不是简单地“把模型变小”，必须用目标任务评测验证收益。

常见精度包括 FP32、FP16、BF16、INT8 和 INT4。训练量化、权重量化、激活量化和 KV Cache 量化的影响不同，不能混为一谈。

## 二、推理关键指标

- TTFT：首 Token 延迟；
- Inter-token Latency：Token 间延迟；
- P50/P95/P99；
- tokens per second；
- 并发下的吞吐；
- 显存占用；
- batch 和 continuous batching；
- KV Cache 大小；
- 单请求成本。

## 三、模型服务链路

```text
客户端
  -> API Gateway / Auth / Rate Limit
  -> Model Router
  -> vLLM / TGI / Transformers Runtime
  -> GPU Worker
  -> Streaming Response
  -> Trace / Metrics / Cost
```

模型服务仍然需要阶段 3、5、7 的权限、评测、Tracing、限流、超时和降级，不应因为模型在本地运行就跳过治理。

## 四、量化实验

固定同一个：

- 基座模型；
- Prompt 和 Chat Template；
- 测试集；
- 最大输入和输出长度；
- 并发数；
- 硬件和服务参数。

对比 FP16/BF16 与 INT8/INT4 的：

```text
质量
  + Tool / Structured Output 正确率
  + 安全通过率
性能
  + 显存
  + TTFT
  + P95
  + 吞吐
成本
  + GPU 时间
  + 单请求成本
```

## 五、练习

1. 对同一个小模型做两种精度的本地推理基准。
2. 比较量化前后的 Tool Calling 和 JSON 合法率。
3. 在并发 1、4、16 下测 P95 和吞吐。
4. 输出一份“质量下降多少才值得节省成本”的决策表。
