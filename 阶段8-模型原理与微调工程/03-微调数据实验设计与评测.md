# 微调数据、实验设计与评测

## 一、数据优先于训练参数

微调失败通常不是因为学习率少调了一个小数位，而是因为数据存在：

- 训练和真实任务分布不一致；
- 标签或工具参数错误；
- 训练集和测试集泄漏；
- 样本风格过于单一；
- 缺少拒答、失败恢复和边界案例；
- 把敏感数据直接放进训练集。

## 二、Agent 微调数据集

建议按能力分类：

| 类别 | 示例 |
|---|---|
| 意图识别 | 判断是否需要工具 |
| 工具选择 | 选择正确的工具 |
| 参数生成 | 日期、租户、资源 ID 正确 |
| 多步执行 | 先查询，再分析，再输出 |
| 错误恢复 | 工具超时或参数错误后的修正 |
| 安全边界 | 越权、注入、敏感操作审批 |
| 格式约束 | JSON、引用、报告模板 |
| 无答案 | 证据不足时明确拒答 |

## 三、实验设计

必须先建立基线：

```text
固定测试集
  -> 基座模型基线
  -> Prompt / Tool Schema 基线
  -> 微调模型
  -> 统一评测和显著差异分析
```

一次实验至少记录：

```text
base_model
adapter_version
dataset_version
train_config
random_seed
hardware
software_versions
training_loss
eval_metrics
```

不要只看训练 Loss。Agent 场景至少看：

- Tool Call Accuracy；
- 参数准确率；
- Task Completion Rate；
- Structured Output Valid Rate；
- 安全用例通过率；
- 无答案拒答准确率；
- P50/P95 延迟；
- 输入输出 Token 和成本。

## 四、数据切分

按任务或业务实体切分，避免同一个工单、同一个模板或同一段日志同时出现在训练和测试中。测试集应保留真实困难样本，不要只留下容易通过的样本。

## 五、微调门禁

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class EvalResult:
    tool_accuracy: float
    task_completion: float
    safety_pass_rate: float
    structured_valid_rate: float


def passes_gate(result: EvalResult, baseline: EvalResult) -> bool:
    return (
        result.tool_accuracy >= baseline.tool_accuracy
        and result.task_completion >= baseline.task_completion
        and result.safety_pass_rate >= baseline.safety_pass_rate
        and result.structured_valid_rate >= 0.98
    )
```

实际门禁还应加入回归阈值、置信区间和人工抽检。微调模型只要安全能力退化，就不能因为平均分提升而发布。

## 六、练习

1. 创建 100 条 Agent 微调样本，按八类能力分布并版本化。
2. 保留 30 条完全独立的测试集。
3. 对基座、Prompt 优化和 LoRA 模型做对照实验。
4. 把失败样本回灌阶段 5 的 Golden Dataset。
5. 写一份“微调没有收益时停止”的决策记录。
